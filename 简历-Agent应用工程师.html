项目定位：面向医院门诊场景的智能体系统，覆盖问诊咨询 → 挂号 → 检查 → 随访主链路， 并为医护提供审批与病历工作台。刻意设定 Tier-0 红线：不做诊断、不开处方、不给用药剂量—— 系统只做流程服务与信息组织，临床判断交还医生。

核心实现

  • 多 Agent 编排：LangGraph 中枢辐射架构，supervisor 做意图分类后分发到分诊 / 挂号 / 诊前 / 随访 4 个子 Agent， 每个 Agent 拥有独立工具命名空间（triage intake booking followup emergency）， 权限按角色收敛；AsyncPostgresSaver 做 checkpointer，会话状态跨服务重启不丢。
  • 人工介入审批（HITL）：医保结算、转诊、120 呼叫等敏感动作用 interrupt() 挂起，审批单落库， 医护在工作台批准后 Command(resume=…) 恢复执行；审批载荷携带完整参数与申请人，避免「盲批」。
  • 三层数据架构 + 合规：Postgres 主库（18 张业务表）+ 每患者独立 SQLite 私有库（PHI 物理隔离，跨患者串号在架构上不可能） + pgvector 向量库（64 条院内知识，9 类）。应用层 EncryptedText 透明列加密（Fernet AEAD，密钥缺失 fail-closed）； 支持留存清理与患者删除权抹除。
  • 对象级授权（OLP）：工具 schema 不含 patient_id / tenant_id，身份只从 JWT 取—— 用白名单思路替代「校验传入 id」，模型被注入也伪造不出参数；22 项越权 PoC 回归测试钉死。
  • 可靠性三件套：重试治抖动、熔断治雪崩、运行时 kill switch 治计划内摘流量； 降级路径绝不编造（LLM 挂了返回兜底话术并引导就医），宁可「不可用」不可「不可信」。
  • 可观测闭环：OTel 链路（chat.turn → agent.<intent> → tool.call / llm.invoke）+ Prometheus 9 条告警 （每条带 runbook_url 直指运维手册）+ Grafana + Alertmanager 三级路由与抑制规则； 自建本地告警接收端，验证「告警真的能送达」而不只是配置正确。
  • LLM 质量体系：用 answerable / unanswerable 配对法量化幻觉率（32 条用例，覆盖接地 / 安全 / 对抗 / 多轮 4 类）， 判定规则完全确定性、不引入 LLM 当裁判；并给检测器本身写自测——先证明「尺子准」，再拿尺子量模型。
  • Prompt 工程化（MLOps）：prompt 从代码字符串抽为版本化文本资产，manifest 记录 SHA-256 并在启动时 fail-closed 校验； CI 卡「改 prompt 必须重跑评测」；上线走灰度发布（按用户 / 租户 / 百分比放量， 用户名稳定哈希保证同一患者体验一致）。
  • 交付与演练：Docker + Helm（7 个 K8s 清单模板 + 3 套环境 values，prod 用本地 Ollama 保证 PHI 不出境）； GitHub Actions CD（镜像按 git SHA 打标 + Trivy 高危阻断 + prod 人工审批）； ArgoCD 拉模式 GitOps；实现备份脚本与恢复演练脚本（自动起临时库 → 恢复 → 健康查询 → 清理）。

代表性 Bug 修复（面试可讲）

  • PHI 隔离漏洞：发现初始迁移把 5 张患者私有表建进了共享主库且存有真实 PHI， 与「物理隔离」的设计承诺直接矛盾。alembic check 永远查不出「库里多了不该有的表」—— 修复分两步且顺序不可颠倒：先写幂等脚本抢救数据（不抢救就删表等于删库），再由迁移删表。
  • Postgres 序列不同步（全新库必崩）：某迁移用裸 SQL 显式插入 id=1 的默认租户， 不推进 SERIAL 序列，导致新建院区时主键冲突。加后续迁移用 setval 对齐序列， 并补护栏测试防止回归——schema 漂移检查查不出数据状态问题。
  • HITL「已批准却没执行」：LangGraph 的 interrupt() 在 resume 时会重跑节点， 若重跑时模型不再生成该敏感调用，动作就丢了。解法：把待审批 tool_calls 落 pending_calls 表， resume 时直接读取执行，保证落库确定性。
