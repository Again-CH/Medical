# 前端工程化 · 构建 / 组件化 / E2E

> 背景：原 `client/chat.html` / `client/review.html` 是「严格 CSP + 事件委托」的纯原生内联脚本（1105 / 879 行），写法克制但工程化展示是减分项。本轮引入 Vite 构建管线、抽取共享模块、补齐 E2E 冒烟测试。

## 1. 构建管线（Vite）

- `client/package.json`：依赖 `vite` + `@playwright/test`；脚本 `dev` / `build` / `test:e2e`。
- `client/vite.config.js`：
  - 双入口：`client/chat.html` + `client/review.html`（`build.rollupOptions.input`）；
  - `base: './'` —— 产物走相对路径，可被网关以「同源子路径」托管；
  - `server.proxy`：`/api` / `/auth` → `http://127.0.0.1:8000`，本地 `vite dev` 直连后端；
  - 构建产物落 `client/dist/`（含 `dist/assets/*.js` 哈希包 + 改写后的 `dist/chat.html` / `dist/review.html`）。
- `node_modules/`、`client/dist/`、`client/test-results/` 已写入 `.gitignore`（构建产物由 `npm run build` 复现，不入 VCS）。

## 2. 组件化（抽取共享模块）

内联脚本被拆分为 `client/src/` 下的 ES 模块，消除 chat/review 间的重复逻辑：

| 模块 | 职责 |
|------|------|
| `src/shared/state.js` | 集中式 `auth` 状态对象（token / username / role / 过期），替代原先散落各处的 `localStorage` 读写 |
| `src/shared/dom.js` | `$()` / `esc()`（HTML 转义）/ `fmtTime()` 等 DOM 工具 |
| `src/shared/api.js` | `API_BASE`/`absUrl`/`apiFetch`（带 401 自动登出）/ `rememberAccount`/`getAccounts` |
| `src/shared/constants.js` | `SERVICES` / `TOOL_NAME` / `VITAL_NAME` / `ACTION_META` 等常量 |
| `src/shared/csp-events.js` | `data-action` 事件委托注册器（严格 CSP 下替代内联 `onclick`） |
| `src/chat.js` | 患者端服务台入口（import 上述共享模块） |
| `src/review.js` | 医护端病历可视化入口 |

入口 HTML 改为 `<script type="module" src="/src/chat.js"></script>`（dev 走 `/src`，Vite build 改写为哈希 `/assets/chat-*.js`）。

## 3. 网关托管（同源，保留 CSP）

`src/gateway.py` 的 `_serve_html` 逻辑：

- `USE_DIST = (client/dist 是否存在)`；
- `dist` 存在 → 托管 `dist/chat.html` 等，并 `app.mount("/assets", StaticFiles(directory=dist/assets))`；
- 否则（未构建的开发态）→ 托管 `client/chat.html`，并 `app.mount("/src", StaticFiles(directory=client/src))` 支持源码直跑；
- 入口脚本为同源 `<script type="module" src=...>`，已被 CSP `script-src 'self'` 放行，**无需 nonce**；仅内联 `<script>` 需要 nonce（保留原注入逻辑）。

> 验证：`npm run build` 后启动后端，浏览器访问 `/` 与 `/review` 均加载同源模块脚本，`/assets/chat-*.js` 返回 `200` 且 `content-type: text/javascript`；E2E 实测通过。

## 4. E2E 冒烟测试（Playwright）

- `client/playwright.config.ts`：`baseURL=http://127.0.0.1:8137`，`webServer.reuseExistingServer: true` 复用由 `client/run_e2e_server.sh` 拉起的本地后端（sqlite + `LLM_MODE=fake`，启动 seed 出 `alice` / `drwang`）。
- `client/tests/smoke.spec.ts`（3 项，全部转绿）：
  1. 患者端页面可加载并展示登录遮罩；
  2. 患者使用演示账号 `alice/alice123` 可登录进入服务台；
  3. 医护端页面可加载并展示登录遮罩。

运行：

```bash
cd client
npm install
npm run build          # 产出 dist/，供网关同源托管
npx playwright install chromium
npx playwright test    # 复用 8137 上的后端（或自动拉起）
```

## 5. 设计取舍

- **为何不引框架（React/Vue）**：项目核心是后端 Agent，前端只是「演示入口 + 病历可视化」。引入框架会增加体积与攻击面，且偏离「严格 CSP + 事件委托」的克制风格。Vite + 原生 ES 模块已满足构建/组件化/E2E 三件事，是最轻的合规解。
- **构建产物不入 VCS**：保持仓库干净，CI 里 `npm ci && npm run build` 复现；缺失 dist 时网关自动回退源码模式仍可跑。
