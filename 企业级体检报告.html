三个值得在面试里主动亮出来的设计决策

  • PHI 物理隔离：患者检验报告、生命体征、随访提醒不进主库，写进 data/<用户名>.db 的独立 SQLite。这是"合规驱动架构"的典型例子，比"加个字段加密"高一个层级。
  • 会话状态用 checkpointer 持久化：HITL 的 interrupt 挂起点存在 Postgres 里，服务重启后患者仍能接着审批后的流程走完。很多人做 HITL 只放内存，重启即丢。
  • Alembic 单一来源 + 漂移门禁：7 个迁移版本，CI 里跑 alembic check，模型和迁移不一致直接阻断合并。（注：当前这道门禁本身有 bug，见下文 R3。）

三、已修复的 5 个红灯

首轮体检的 5 个红灯，表面看是 5 个独立问题，追下去其实是 3 个根因。修复已全部合入 c00b839。

根因一：测试依赖"数据库全新"这一隐含前提（R1 / R4）

已修测试不可重复执行
第二次跑全量测试就有 5 处失败，而第一次全绿。逐项追下去发现是四类运行时状态被上一个测试留下：挂号幂等键（TTL 1h，第二次跑命中缓存直接返回首次结果、不落库 → e2e「批准后未真实落库」）、号源占用与当日预约上限、防爆破的 failed_attempts（登录返回 423）、以及 token_version（登出会 bump 它，而网关测试签发的令牌固定带 tv=0 → 全员 401）。
修法：tests/conftest.py 新增 autouse fixture，每个用例前重置这四类可重建的运行时状态，绝不动账号、审计日志、知识库等核心资产。另加 MC_TEST_DB 护栏——指向非 sqlite 库时必须显式设 MC_TEST_DB=1，否则 fail-fast，防止有人误把测试跑在含业务数据的库上。

根因二：pgvector 迁移没做方言适配（R3 / test_store）

已修sqlite 跑不通迁移、漂移检查误报
f6a7b8c9d0e1 迁移无条件执行 CREATE EXTENSION vector 与 USING hnsw，sqlite 下必然报错；而漂移检查又把每患者私有 SQLite 的模型（lab_reports / vital_signs / reminders / conversation_memory / emergency_events）当成主库表，判定"被删除"。顺带还暴露出真实的模型漂移：knowledge_documents 三列的 nullable 与迁移不一致。
修法：迁移按方言跳过（非 Postgres 直接 return）；alembic/env.py 的 include_object 排除 PatientBase 私有表与 pgvector HNSW 索引；ORM 模型补 nullable=False 与迁移对齐。现在两种方言的漂移检查都通过。

根因三：接口语义靠字符串嗅探（R4 之一）

已修账号已存在返回 400 而非 409
register_user 抛 ValueError("user exists")（英文），网关靠判断消息里是否含中文"已存在"来决定 400 还是 409 —— 一次文案改动就能让接口语义悄悄退化。已新增 UserExistsError 类型化异常，网关按异常类型回 409，契约不再脆弱。
实测：重复注册现返回 409 {"detail":"用户已存在"}
已修ruff 门禁 + Git 历史 + CI 镜像
ruff check 4 处错误（含 import 排序、未使用的循环变量）与 format 不一致的 9 个文件已修；69 个未提交改动（含 6 个 untracked 迁移文件）已整理提交；CI 的 integration job 原本用官方 postgres:16 镜像，不带 pgvector 扩展，升级必失败，已换成 pgvector/pgvector:pg16；README 的 CI 徽章占位符与"本地一键验证"章节已补齐。
验证：git clone 到空目录后 pytest -q 直接 80/80 全绿

四、距离真正的企业级，还差什么

按面试含金量排序——越靠前，越能换来"这个人有生产经验"的评价。

P1 · 做了就能把档次拉上去

  • 可观测性三件套：暴露 /metrics（prometheus_client）统计请求量、SSE 时长、审批等待时长、红线命中率；用 OpenTelemetry 把一次请求贯穿 supervisor → 子 Agent → 工具调用 → LLM 的四段 span 串起来；日志统一带 trace_id。目前只有 /health，等于"上线即盲飞"。
  • LLM 侧可观测与成本：按患者 / 按 Agent / 按模型的 token 消耗与费用归因，接入 LangSmith 或 Phoenix。医疗场景的幻觉率和成本是老板最关心的两个数字，有这个数据你就能讲业务语言。
  • 性能基线与压测报告：用 k6 或 locust 出一份 p50/p95 延迟、SSE 并发上限、checkpointer 写放大、pgvector 检索耗时的报告。哪怕数字不好看，有基线本身就是工程成熟度。
  • 韧性工程：LLM 超时熔断、失败降级到规则引擎、kill switch 一键停掉某个 Agent 的工具权限。现在有 retry.py 和 fake 兜底，但缺熔断与降级编排。

P2 · 从"能跑"到"能交付运维"

  • 部署与 IaC：Helm chart / Kustomize、多环境配置分离、Secret 走 Vault 或 KMS 而非 .env。
  • 数据合规深化：PHI 列级加密、密钥定期轮换、数据留存与删除 SLA（现在有 DELETE /api/patient/me，但缺留存策略和备份清理的联动）、备份恢复演练记录。
  • 多租户与水平扩展：现在是单院模型，departments 表没有 tenant 维度。多院区是医疗信息化的刚需。
  • 前端工程化：构建流程、组件化、E2E 测试。当前严格 CSP + 事件委托的写法很克制，但对"工程能力"的展示是减分项。

三个必背故事（每个都要能说出文件和数据）

  • HITL 中断恢复：讲 interrupt 挂在审批门 → 状态写进 Postgres checkpointer → 医护端 /api/review/resolve 批准 → Command(resume=...) 恢复 → 服务重启也不丢。配一句"审批单 payload 里带完整 args 和 requester，resolve 时记 resolved_by，审计可追溯"。
  • PHI 隔离与越权防护：讲工具 schema 里没有 patient_id 参数，身份只从 JWT 取（对象级授权 OLP），thread_id 派生为 {role}:{sub}:{client_tid}；再配 tests/test_security_isolation.py 里 293 行越权 PoC 回归。这是本项目最硬的一块。
  • 幂等与审批审计：讲挂号用 idempotency_keys + 号源 booked_slots 悲观锁防超卖，配合 approvals 表与 194 条 audit_logs 形成完整证据链。
  • 合规驱动的 schema 治理（本轮新增素材）：三层数据架构（主库 / 每患者私有 SQLite / 向量库）决定了「哪些表该进迁移、哪些不该」。讲你如何让 alembic check 理解这个边界——私有模型挂在独立 PatientBase 下、pgvector 迁移按方言跳过、HNSW 索引排除在比对之外。这类"让工具理解架构意图"的活儿，比堆功能更能体现功力。

四个会被追问的坑，提前备好答案

"你的测试现在是全绿吗？"
可以硬气了：80/80，sqlite 与 Postgres 双路径，连续跑两次都全绿，clean clone 也能一键跑通。顺手补一句修复过程——之前测试只能跑一次，第二次就挂 5 处，根因是四类运行时状态跨用例残留（幂等键、号源、账号锁定、token_version），解法是每个用例前重置可重建状态 + MC_TEST_DB 护栏防止误跑业务库。这个问题本身就是很好的谈资。
"你的 CI 有几道门禁？"
六道：lint（ruff check + format）、3 个 Python 版本测试矩阵、schema 漂移检查、离线评测门禁、真实 PostgreSQL 集成测试、安全三件套（bandit + pip-audit + gitleaks）+ 越权回归。可以提一句 CI 里踩过的坑：官方 postgres:16 镜像不带 pgvector，集成任务必须换 pgvector/pgvector:pg16。
"上生产你怎么观测它？"
别硬撑。答："目前只有结构化日志和 health 检查，这是我列的第一个 P1——metrics 用 prometheus_client，链路用 OTel 把 supervisor 到工具调用串起来，LLM 侧接 Phoenix 做 token 和幻觉归因。"主动承认缺口 + 给出方案，比吹牛安全得多。
"QPS 多少？p95 延迟多少？"
没数据就别编数字。答："还没做压测，这是第二个 P1。架构上的瓶颈点我已经识别出来是 checkpointer 的写放大和 pgvector 检索，计划用 k6 出基线。"
"这跟一个 CRUD 项目有什么区别？"
答在三点：① 非确定性输出的治理（Tier-0 确定性红线 + 输出侧护栏双层拦截）；② 长事务与人工介入（HITL + 状态持久化）；③ 合规驱动的数据分层（PHI 私有库 + 脱敏 + 出境策略）。
